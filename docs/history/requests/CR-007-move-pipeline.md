# CR-007: move the pipeline into `ponzi.pipeline`

- **Requested by / date:** owner, 2026-10-12
- **Status:** implemented 2026-10-12, awaiting owner review
- **Stale:** the `ponzi.pipeline` subpackage it moved in was replaced the same day by `ponzi.onboarding`, which later became the onboarding of the `ponzi-pipeline` distribution (CR-008, CR-029).

## Why
Next step of the restructure (monorepo `docs/target_architecture_2026-10-09.md`): one library with subpackages. The work before the run (sensors, catalogue, validation, onboarding) is the monorepo package `ponzi_pipeline`; it becomes the subpackage `ponzi.pipeline` so that it is versioned and tested with the contracts and the run it feeds.

## What changes
A mechanical move from the monorepo at `ef99d21`. Nothing is removed and nothing is redesigned.

- `packages/ponzi_pipeline/src/ponzi_pipeline/` (15 modules, 8,684 lines) becomes `src/ponzi/pipeline/`; `packages/ponzi_pipeline/tests/` becomes `tests/pipeline/`, a subfolder with its own `conftest.py`, helper modules and `data/`.
- Imports: `ponzi_pipeline.X` is `ponzi.pipeline.X`; the old core modules are `ponzi.core.X` (`runner`, `cli`, `sample`, `context`, `forecast.fm_windows`); `ponzi.contracts` and `ponzi.evaluation` keep their names. The docstrings and the logger names in the tests follow.
- The command `ponzi-pipeline` stays, now `ponzi.pipeline.cli:main`.
- Dependencies: the optional extra `pipeline` in `pyproject.toml` (shapely, geopandas, pyproj, rasterio, asf_search, cdsapi, requests, netcdf4, fsspec, aiohttp), and the same packages in the default pixi environment with the monorepo's version bounds, so `pixi run test` runs the pipeline tests. The environment may hold the geospatial stack; importing `ponzi.contracts`, `core`, `evaluation`, `calibration` or `models` still must not load it.
- Layering: `pipeline` may import `contracts`, `core` and `evaluation` (it needs `evaluation` for the AOI aggregation and the event evaluation). No other rule changes. It imports nothing of `calibration`, `models` or `products`.
- `configs/request/{bright,majortom,default}.yaml` are copied because three tests read the shipped request configs.

### Kept on purpose
Names that are written into stores and files stay as they were, so a request or a sidecar made after the move is the same as one made before: the sidecar attribute `producer` and the `era5_pd_source` provenance (`ponzi_pipeline.onboard`), the `package_versions` key `ponzi_pipeline` in `request.json`, and the "Generated by `ponzi_pipeline....`" line of the derived markdown files. `ponzi.pipeline.__version__` is still the fixed `0.1.0` that goes into `request.json`. Whether these follow the new name is the owner's call (a change to recorded metadata).

The contract files in `docs/contracts/` were copied wholesale earlier and are identical to the monorepo's; they still say `ponzi_pipeline` and `ponzi.runner` and are left for the documentation pass.

### Path assumptions, to fix in a later request
The move keeps the lookups as they are. Each of them assumes a source checkout or a working directory with `configs/` in it:

1. `pipeline/run.py`, `config_dir()`: the run config directory is the argument, else `PONZI_CONFIG_DIR`, else `Path(__file__).resolve().parents[3] / "configs" / "run"` (was `parents[4]`). The fallback is the repository root only for an editable install; from a wheel it points beside `site-packages`. This repository holds one run config (`exp_b5h5_base.yaml`); the monorepo holds 72 and `experiments.yaml`.
2. `pipeline/request_config.py`, `CONFIG_DIR = Path("configs") / "request"`: a config named without a path is searched in `configs/request/` above the working directory, then above the module file. Unchanged; the second search only finds something in a source checkout.
3. `pipeline/paths.py`, `DEFAULT_ROOT = Path("data")`: without `PONZI_DATA_ROOT` the data root is `./data`.
4. `tests/pipeline/test_registry_and_plan.py` and `test_selection.py`, `REPO = Path(__file__).resolve().parents[2]` (was `parents[3]`): they read `configs/request/{bright,majortom,default}.yaml` from the repository. The campaign files are named after datasets and belong to `ponzi-apps`; the tests should then carry their own copies.
5. `tests/pipeline/test_registry_and_plan.py`, `REF_REQ`: `PONZI_REF_REQUESTS`, else `~/projects/ponzi-ccd/data/pipeline/requests`. Two `slow` tests compare against that reference and are skipped when it is absent (see Tests).
6. `tests/pipeline/data/build_asf_fixtures.py`: the fixture builder reads `~/projects/ponzi-ccd/data/majortom/burst_db/bursts.parquet` by default and puts `parents[3] / "src"` on the path. It is a script, not a test.
7. Messages and docstrings that point at monorepo documents: `docs/decisions.md` (`selection.py`, `__init__.py`) and `docs/implementation.md` (`__init__.py`).

### Left for the clean-up requests
- The pipeline code names no dataset in identifiers, but comments and docstrings mention BRIGHT, Major-TOM, Noto and the paper package (`onboard.py`, `validate.py`, `request_config.py`, `selection.py`, `evaluation.py`, `aoi.py`), and the test fixtures are BRIGHT tables (`tests/pipeline/data/bright_*`). `pipeline/evaluation.py` (716 lines, burst to event and across events, monorepo decision 29c) is evaluation rather than "before the run" and came from the paper's `claim2_pyramid`; where it lives is a later decision.
- The two reference comparisons under point 5 are of the kind CR-001 removed from the core tests.
- `pipeline/cli.py` and `pipeline/run.py` use `ponzi.core.cli` (`CommandArgs`, `add_model_arguments`, `resolve_args`, and `main` for `ponzi eval`), not the new `ponzi.cli`.

## Do results change?
No. Import paths, two `parents[N]` indices and the entry point only. No golden file is touched.

## Tests
The 11 test modules of the package with their `conftest.py`, two helper modules and `data/`, as `tests/pipeline/`; no file had to be renamed (no basename is shared with `tests/`). `pixi run test` collects both folders: 524 passed and 2 skipped (the two torch modules, as before) in about 2 minutes, of which 299 are the tests that were here and 225 are the pipeline's. Before the move the fast tier was 299 passed, 2 skipped, under a minute. Six pipeline tests are marked `slow` as they were (19 seconds together, `pixi run test-full`).

- No test touches the network: the ASF and CMR call sites, the GHSL tiles and the ERA5 sources are replaced by fixtures, as in the monorepo.
- Two `slow` tests need data outside the repository and are skipped without it: `test_plan_reproduces_the_frozen_bright_manifest` and `test_the_event_gate_never_binds_on_bright` (`test_registry_and_plan.py`, path assumption 5).
- One test was adapted to the environment, not to the move: `test_the_sample_carries_a_legacy_stores_string_pair_tables`. The lock file here has zarr 3.4.1 and xarray 2026.9.0 (the monorepo: 3.3.0 and 2026.7.0), under which the string tables of a zarr v2 store arrive as the variable-length string dtype instead of numpy `object`, and the sample store keeps that dtype instead of the fixed-width cast. The test now expects the cast when the table arrives as `object` and the unchanged dtype otherwise. No library code was changed for this; whether a sample with variable-length string tables is what the run should get is open.

## Version
Library: minor (a new subpackage; every existing run config is untouched). Standard: no effect.
