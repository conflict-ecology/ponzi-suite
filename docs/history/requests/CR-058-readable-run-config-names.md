# CR-058: readable names for run configs

- **Requested by / date:** owner, 2026-11-05 ("make a human readable naming convention" for run configs, after CR-052 named forecasters, panels and models).
- **Status:** implemented on the owner's instruction (2026-11-05)

## Why

The one run config in ponzi-suite was named `exp_b5h5_base`, a code for "experiment, 5 baselines, horizon 5, base". Run configs had no naming rule, unlike forecasters, panels and models (CR-052).

## What changes

- **The rule:** a run config is named `<forecaster>-<scoring>[-<change>...]` (`ponzi_spec.naming.run_config_name`). The forecaster part is the forecaster it runs. The scoring word says how it scores: `pyramid` is the 15-pair pyramid over baselines of 12 to 60 days and a horizon of 5. A variant adds its change.
- **The file:** `run_configs/<name>.yaml`, the name being its stem.
- **The rename:**
  - `exp_b5h5_base` becomes `rolling-ols-pyramid`, in ponzi-suite and in ponzi-core's test copy (`packages/core/tests/data/rolling-ols-pyramid.yaml`).
  - Its header records the former name, and the stale "generated by ponzi-paper" header is replaced.
  - The contract C4 and the naming page follow.

## Do results change?

No. A run config's name is a label and is left out of its hash (`config_hash` excludes `name`), so the golden hash of the test copy is unchanged.

## Tests

- ponzi-spec `test_naming.py`: `run_config_name`.
- ponzi-models `test_suite_names.py`: every suite run config is named by its file, readable, and starts with its forecaster.
- ponzi-core `test_config.py`, `test_testcases.py`, `test_rolling.py` on the renamed files; the golden hash is unchanged.
