# Training and calibrating a model

From a training spec to a model watched areas run, with the command `ponzi-models` (`ponzi-models --help` lists the stages).

The steps below are written for a trained forecaster, such as TiDE, today's default. Any forecaster can take its place: a new kind is added as a module of `ponzi.core.forecast` with one `register(name, cls, params)` call, and then follows the same steps (one that fits itself as it runs, like `rolling_ols`, skips training and export). The scoring, the calibration, the detection and the service do not change with the forecaster.

1. **Change request**, with the evidence the model is meant to improve on.
2. **Training spec** in ponzi-suite `specs/training_specs/<family>/` (a variant in `candidates/`, built on its base with `extends:`), named by the [naming convention](naming.md) and given to the commands as `--training-spec NAME|FILE`: window (context, horizon, baselines, quantile levels), covariate channels, sizes, optimiser, stopping, treatment of missing values, augmentation. Unknown keys are refused.
3. **Panel**: a set of pixels of many bursts, defined by mask layers on full coherence stores. Its panel spec is the folder ponzi-suite `specs/panel_specs/<id>/`, checked with `ponzi-models panel-check`; `ponzi-models panel-build --panel-spec <id>` builds it into `$PONZI_HOME/panels/<id>@<hash8>` ([Training panels](../method/panels.md)). Training, calibration and production read the panel through the same opener, so a training window is byte for byte the window inference builds.
4. **Prepare, train, export** (`ponzi-models prepare`, `train`, `export`): the prepared files are identified by a digest of what they depend on; training keeps the epoch with the lowest validation loss; export writes the artifact (for TiDE, TorchScript and its `meta.json`). Without `--out` and `--models-root`, the prepared files and the fits go to `$PONZI_HOME/training/` and the artifacts to `$PONZI_HOME/models/` (CR-080).
5. **Register** (`ponzi-models register-model`) the model, its id `<training spec>@<hash8>--<panel spec>@<hash8>` ([Naming rules](naming.md); the name `export` gives the artifact) in the registry (`$PONZI_HOME/registry` by default) with its model card: the artifact by its digest, the scoring spec it runs with (filed as `scoring_spec.yaml`), the training spec it was fitted with (filed as `training_spec.yaml`, when its fit recorded one), and the `specs:` block of its training, scoring and panel specs ([Specs: a name and a hash](versions.md#specs-a-name-and-a-hash)). Scoring specs refer to the model as `registry:<model id>@sha256:<digest>` (`ModelEntry.ref`), never by path; the run resolves it through the registry and checks the digest.
6. **Null and calibrate** (`ponzi-models null-runs`, `null-rows`, `calibrate`, `register-calibration`): run the registered model over the panel's test bursts; build the calibrations (plain and ceiling) from those runs. For staged runs (CR-021), `null-runs --staged` and `calibrate-staged` build the staged pair instead. A calibration is bound to one scoring spec hash and one major version of `ponzi`.
7. **Benchmark** against the current standard. A model joins a standard only after the benchmark. There is no benchmark command yet.
8. **Standard**: a yaml file in ponzi-suite `standards/<id>.yaml`, written for a new id by `ponzi-models new-standard` from the registry (by default into `$PONZI_HOME/specs/standards/`, CR-089); a new version is an edit of the file, its version its content hash ([Writing and registering a version](versions.md#writing-and-registering-a-version)). It names its panel spec, the model, its scoring spec hash, its calibrations, its detection, coherence and onboarding specs, and the library versions it `requires`. It starts as a draft (`status: draft`), is published once its model and calibrations are registered, and is filed with `register-standard`. `check-standard` holds it to [the checks of a standard](standards.md) and reports what it changes from the version before it. `ponzi-models standard-workflow` turns it into the file the server runs, in the server's `$PONZI_HOME/standards/`.
